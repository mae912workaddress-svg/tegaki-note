# てがきノート（第2段階）

iPad と Apple Pencil のための、日本語の手書きノート PWA です。ビルドは不要です。アプリのノート、ページ、フォルダは、この配信元の IndexedDB `tegaki-note`（スキーマ版1）だけに保存します。ノート内容を送信する処理、解析サービス、CDN はありません。

## PC で確認する

Node.js 20 以上を用意し、このフォルダで次を実行します。同梱済みの `vendor/` とアイコンがあれば、動作確認に npm install は不要です。

```powershell
node scripts/serve.mjs
```

PC のブラウザーで **http://127.0.0.1:4173/** を開きます。マウスで描画できます。終了はサーバーのターミナルで Ctrl+C です。ポートを変える場合は `$env:PORT=4180` を設定して起動します。サーバーは `127.0.0.1` だけで待ち受けます。

**PC の localhost / 127.0.0.1 は、iPad からは開けません。** iPad では GitHub Pages などの HTTPS 配信が必要です。

```powershell
node --test
```

テストでは配布部品とnpmの原本も照合します。クローン直後など `node_modules/` がない場合は、先に下の「部品の再生成」のnpmコマンドを実行してください。純粋モデル、保存処理の失敗時動作、キャッシュ、配布資産、ローカルHTTPなどを確認します。iPad 実機の筆圧・パームリジェクション・オフライン起動・100ページの操作感は、これとは別の確認項目です。

## iPad で使う

1. iPadOS 17 以上の Safari で、公開済みの HTTPS アドレスを開きます。
2. Safari の共有ボタンから「ホーム画面に追加」を選びます。
3. オンラインでアプリを一度起動し、オフライン用データの準備が完了してから使います。初回はPDF用部品も保存するため時間がかかる場合があります。
4. 「新しいノート」で A4 縦・横、無地・方眼5mm・横罫7mm・ドット方眼5mm、表紙色を選びます。
5. 初期設定では Apple Pencil で描き、指1本でスクロール、指2本で拡大・縮小します。「指でも描く」をONにすると指1本でも描画できます。2本指は引き続き拡大・縮小用です。この設定は編集画面を開くたびにOFFになります。
6. 右下の「消しゴムに切替」を押すと消しゴムになり、もう一度押すと直前のツールへ戻ります。Apple Pencil ダブルタップの代わりに使えます。
7. 消しゴムは「線ごと消す」「部分を消す」を選べます。消しゴム半径は太さ設定に連動します。投げなわで線全体を囲むと選択でき、選択した線上をドラッグして移動、「選択を削除」で削除します。
8. Undo/Redo はページ単位です。ページを削除したり画面を閉じたりすると、その履歴は残りません。ノート・ページ・フォルダの削除には個別の確認があります。
9. 線を確定して約500ms後に自動保存します。「保存済み」を確認して終了してください。保存に失敗したら画面を閉じず、空き容量を確認して「再保存」を押してください。OSの強制終了時に未確定の線まで保存できる保証はありません。

一覧の各ノートの「…」から書き出し・名前変更・複製・フォルダ移動・表紙色変更・削除ができます。フォルダ削除時は中のノートを未分類に戻します。検索はノート名・テキストボックス・取り込んだPDFの文字を対象にし、全角/半角・大文字/小文字の違いを吸収します。結果を押すと該当ページへ移動します。手書き文字と画像化されたPDFの文字は検索対象外です。

端末内データはブラウザーのサイトデータ削除で消えます。起動時に永続保存を要求しますが、拒否・未対応でも動作を継続します。一覧上部の「…」→「バックアップ」で定期的に保存してください。

## 読み込み・ページ・画像・文字

- 一覧の「読み込み」でPDF/JPGを選ぶか、一覧へドラッグ＆ドロップします。PDFは1ファイル1冊、同時選択したJPGは1冊にまとめます。混在選択の場合はPDFごとのノートとJPGのノートをまとめて確定し、最初のノートを開きます。途中の読み込み失敗ではノートを追加しません。
- メールで添付を開く → 共有 →「ファイルに保存」→ このアプリの「読み込み」。iPadのSplit Viewでは添付を一覧へドラッグできます。パスワード付きPDF、破損ファイル、未対応形式は拒否します。
- PDFは回転を反映したページ寸法を保持します。JPGはEXIFを反映したブラウザーの描画結果を再保存し、縦長ならA4縦・横長ならA4横に収めます。JPEG/PNGはデコード前にヘッダーを検査し、5000万画素超を拒否します。保存画像の長辺は最大4096pxです。
- 「ページ一覧」のサムネイルを押すと移動します。「↕」をPencil/指でドラッグ、または↑↓で並べ替え、複製・削除できます。「☆ しおり」で付け外しし、ページ一覧でしおりだけ表示できます。
- 「画像」でJPEG/PNGをページ中央へ配置します。「選択」で画像・文字を選んでドラッグし、画像＋/−で縦横比を保って拡大縮小します。「テキスト」で用紙をタップすると入力でき、選択後の「項目を編集」で文字・サイズ3段階・色を変更できます。
- 投げなわで線・画像・文字を囲んでまとめて移動・削除できます。画像・文字の追加、編集、移動、サイズ変更、削除はページ単位のUndo/Redo対象です。

## 書き出し・共有・復元

- 編集画面の「書き出し」または一覧の各ノートの「…」→「書き出し」で、PDF/JPGと全ページ/現在のページを選び、「作成」を押します。一覧での「現在のページ」は先頭ページです。
- 作成完了後の「共有」を別途タップします。共有メニューの「メール」から添付付きの作成画面を開き、宛先・件名・本文を入力してください。ファイル共有が非対応ならダウンロードを開始します。JPGの複数ダウンロードが制限される場合に備え、各ファイルの保存ボタンも表示します。
- PDF背景は可能な場合ベクターで埋め込みます。所有者パスワードによる暗号化や埋込み非対応の背景は、PDF.jsの描画を画像化して出力します。用紙と手書き線はベクターで出力します。日本語テキストは高解像度画像です。JPGは約200dpi、1枚最大400万画素・長辺4096pxで、ページごとのファイルになります。
- 一覧上部の「…」→「バックアップ」で、全フォルダ・ノート・ページ・ファイルをJSONにまとめます。作成後に「共有」で保存します。ファイルは1件ずつbase64へ変換しますが、JSON全体と保存データをメモリーに保持するため、大容量では端末の空きメモリーが必要です。
- 「復元」でJSONを選ぶと、形式・版数・必須4ストア・値・件数・参照・base64を検査します。バックアップv2は各ファイルのSHA-256とバイト長を保存し、復元前に全件照合します。旧v1も読み込めます。PDFは全ページのPDF.js演算子取得、画像はデコードで検証します。「現在のノートはすべて置き換えられます」の確認後、1トランザクションで置き換えます。検証失敗または保存失敗なら既存データは維持されます。復元後のUndoはありません。

## GitHub Pages 公開手順（参考・今回は公開しません）

実際のリポジトリ作成・アップロード・公開は、ユーザーの確認後に行ってください。

1. このフォルダをリポジトリの配信対象にします。`index.html`、`src/`、`vendor/`、`icons/`、`sw.js`、`precache.js`、`manifest.webmanifest` をすべて含めます。`node_modules/`、`.npm-cache/` は含めません。
2. リポジトリの Settings → Pages で配信ブランチとルートフォルダを選びます。
3. `https://ユーザー名.github.io/リポジトリ名/` のように末尾 `/` を付けて開きます。相対URLと `scope: "./"` なのでサブパスでも動作します。
4. 更新を公開する前に `sw.js` の `CACHE` の版を上げ、下記の再生成とテストを実行します。ネットワーク優先で取得し、取得できない場合だけキャッシュを使います。新しいService Workerは編集中に強制切替せず、全画面を閉じた後に有効になります。

## 部品の再生成

直接依存は承認済み3点だけです。npm が必要とする推移的依存は `package-lock.json` で固定します。依存を更新するときは Safari 対応を再確認してください。

```powershell
npm install --save-exact --ignore-scripts --omit=optional --no-audit --no-fund --cache ./.npm-cache pdfjs-dist@4.10.38 pdf-lib@1.17.1 perfect-freehand@1.2.2
node scripts/make-icons.mjs
node scripts/copy-vendor.mjs
node --test
```

`copy-vendor.mjs` は PDF.js **legacy build** 本体・worker・CMaps・標準フォント、pdf-lib の ES Module、perfect-freehand の ES Module と LICENSE をコピーし、全配信資産の `precache.js` を生成します。PDF.js 4.10.38のworker・CMaps・標準フォントはすべて同梱ファイルから取得します。

## 構造と拡張点

- `src/model/`: A4寸法、用紙線・点、ストローク分割、投げなわ、ノート操作、履歴、保存値・参照検証。DOMやIndexedDBを使いません。
- `src/storage/`: 4ストアを管理し、ページと `notebook.updatedAt` を同一トランザクションで確定します。失敗した自動保存のスナップショットを保持し、再保存できます。
- `src/render/`: pt座標を共通描画。入力の重複・極端な座標外れ値を除き、筆圧を軽く平滑化してperfect-freehandへ渡します。描画中・確定後・PDF書き出しで同じ輪郭計算と終端taperを使い、保存済みの線も描画時に補正します。蛍光ペンは筆圧なし・不透明度0.35です。
- `src/ui/`: 一覧と編集。ページのDOM枠だけを保持し、現在付近の最大5ページ（入力中のページは追加保持）にキャンバスを限定します。各レイヤーは表示倍率×devicePixelRatioで描画し、最大400万画素・長辺4096pxの上限を設け、画面外ではサイズを0にして解放します。倍率変更はキャンバス再描画です。大倍率ではメモリー上限を優先します。
- `src/import/`: PDF/JPGの取り込みと画像の向き・縮小処理。`src/export/`: DOM非依存のPDF組み立て、ページ画像生成、ファイル共有。`src/storage/backup.js`: バックアップの符号化・完全検証。
- `files` は `{id,mime,blob,name}`（画像ではwidth/heightも保存）。PDF背景は `{type:'pdf',fileId,pageIndex}`、画像背景は `{type:'image',fileId,x,y,w,h}`。元PDFはそのまま保持し、画面付近の背景だけ描画・解放します。
- 新規itemsは画像 `{id,type:'image',fileId,x,y,w,h}`、文字 `{id,type:'text',text,x,y,w,h,fontSize,color}`。従来のwidth/height名も読み取れます。文字のhは折り返し後の選択範囲です。画像ファイルはUndoとノート複製の参照を保つため、項目削除時には消去しません。
- 不正データや参照切れは警告して表示から除外し、保存データ自体は削除しません。必要なページが不正な場合、そのノートも除外して不完全なノートを上書きしないようにします。

## 実機指摘への修正（v1.3.0）

PDFの取込みは、同梱PDF.jsで全ページのgetPage/getOperatorListが成功することを判定基準とします。独自のFlateチェックサム検証は行いません。空のユーザーパスワードで開ける所有者パスワード付きPDFも対象です。入力が必要なPDFは「パスワード付きPDFは読み込めません」と案内します。

PDF.jsが警告付きで処理を続けるPDFは受理します。PDF.js自身が無視するストリームの内容を復旧する機能ではありません。テストのraw deflate例はPDF.jsが警告して本文を無視するため、その例の背景内容の再現は保証できません。バックアップv2は保存後のバイト変化を検出しますが、ハッシュのないv1ではPDF.jsが許容するストリームの破損まで判別できません。

ペンの筆圧0をマウス向けの0.5へ置換せず、離筆座標が必要な場合は直前の筆圧を継承します。描画中レイヤーは各描画フレームで全消去して輪郭を再描画し、確定・取消時にも消去します。倍率・DPR変更時は両レイヤーと背景を再描画します。高倍率ではキャンバスの上限により実ピクセル密度が下がります。

回帰テストは暗号化・Adler欠落・末尾データ・Object/XRefストリーム、保存後の本文破損と全ストア保持、旧版復元、描画フレーム・終端筆圧を検証します。Node環境でCanvasのPNG出力はテスト用出力に置き換えており、iPad実機の画素・書き味は再評価が必要です。
